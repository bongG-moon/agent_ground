# 현재 녹취 기대 결과 예시

모델마다 표현은 달라질 수 있지만 `current_transcript.txt`를 처리하면 아래 사실과 구조가 유지되어야 합니다. 이것은 정답 문구를 외우게 하는 프롬프트가 아니라 생성 결과를 사람이 대조하기 위한 기준입니다.

```markdown
# 자동 회의록 운영 시범 전환 의사결정 회의

- 일시: 2026-06-17
- 참석: 서팀장, 문과장, 조책임, 임대리, 송매니저
- 목적: 자동 회의록 기능의 운영 시범 범위, 품질·보안 기준, 일정과 담당자를 확정함

## 현황 요약
- 내부 회의 12건 검증 결과, 회의록 작성 시간은 평균 58분에서 검토 포함 19분으로 감소함.
- 의사결정은 86건 중 81건, 담당자·기한이 포함된 액션아이템은 104건 중 91건이 정확히 반영됨.
- 날짜·수치 오류와 과거 예시의 사실이 현재 회의록에 섞인 사례가 있었으며, 이후 과거 자료에서는 스타일만 추출하도록 구조를 변경함.

## 주요 논의
- 시범 대상은 내부 운영 및 시스템 개선 정기회의로 제한함.
- 외부 고객, 인사, 평가, 징계, 채용, 법무, 감사 관련 회의는 제외함.
- 과거 녹취와 과거 회의록은 각각 최대 10개까지 같은 순서로 넣으며, 현재 녹취는 한 개만 처리함.
- 사내 승인 모델과 사내망만 사용하고, 사내한 이하이면서 사전 등록된 회의만 처리함.
- 일반 문서는 로컬에서 먼저 읽고 보호 Word 문서만 필요할 때 DRM API로 처리함.
- 생성 결과는 작성자 검토와 회의 주관자 승인 후 문서관리시스템에 등록함.

## 의사결정
- 운영기획팀 8명과 IT서비스개선팀 7명, 총 15명을 대상으로 약 8건의 회의를 시범 처리함.
- 운영 점검 완료를 전제로 2026-06-24부터 2026-07-07까지 2주간 진행함.
- 의사결정 반영률과 액션아이템 반영률은 각각 95% 이상이어야 함.
- 사람·날짜·수치·결정과 과거 사실 혼입에 관한 중대 사실 오류는 0건이어야 함.
- 12만 자 이하 녹취의 95%를 8분 이내 처리하고 전체 처리 성공률은 98% 이상으로 관리함.
- 개인정보 외부 전송 또는 권한 위반이 발생하면 전체 시범을 즉시 중단함.
- 같은 유형의 중대 사실 오류가 두 번 발생하거나 하루 성공률이 90% 미만이면 신규 실행을 중단함.
- 확대 여부는 자동 결정하지 않고 2026-07-09 평가 회의에서 판단함.

## 후속 조치
| 담당 | 조치 | 기한 |
| --- | --- | --- |
| 문과장 | 평가표와 기준 회의록 준비 | 2026-06-22 |
| 조책임 | 운영 서버 임시 파일 정리, 로그 설정, 실패 알림 확인 | 2026-06-23 |
| 임대리 | 기본 추가 지시문과 사용자 검토 체크리스트 준비 | 2026-06-22 |
| 송매니저 | 참여자 확정, 사전 등록 회의 목록 배포, 30분 교육 완료 | 2026-06-23 |
| 서팀장 | 운영 시범 승인 요청 및 문서관리 담당 부서 협의 | 승인 요청은 회의 당일, 협의는 2026-06-22 |

## 확인 필요
- 운영 서버의 임시 파일 잔여물 정리 작업 반영 여부
- 보안 등급 자동 판별 기능의 범위, 담당 부서와 일정
- 향후 외부 고객 회의를 확대 대상에 포함할지 여부
```

확인할 점:

- 과거 예시의 고객 문의 분류율, 영업 금액, 거래처 매핑 등 과거 사실이 현재 문서에 들어가지 않음
- 현재 녹취의 시범 범위, 제외 회의, 정확도·성능 기준과 중단 조건이 포함됨
- 담당자와 기한이 현재 녹취의 내용과 정확히 일치함
- 미확정인 운영 서버 점검 결과와 장기 보안 기능에 임의의 완료 상태나 날짜가 생성되지 않음
- 커피 머신, 점심 장소, 휴가 일정 등 잡담이 포함되지 않음
- 과거 회의록에서 관찰되는 섹션 순서, 간결한 `~함` 종결, 표 기반 후속 조치 형식이 반영됨
