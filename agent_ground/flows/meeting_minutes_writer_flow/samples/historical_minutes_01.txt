# 고객 문의 자동 분류 개선 주간회의 회의록

- 일시: 2026-06-03
- 참석: 박팀장, 김주임, 이대리, 최과장, 정매니저
- 목적: 고객 문의 처리 지연 원인을 확인하고 저정확도 유형의 분류 규칙, 야간 자동 이동, 시범 운영 기준을 확정함

## 1. 현황 요약

- 5월 고객 문의는 8,420건으로 전월 대비 11% 증가했으며 평균 최초 응답 시간은 14.2시간에서 18.1시간으로 늘어남.
- 업무시간 내 접수 건의 최초 응답 시간은 9.6시간, 야간 접수 건은 27.4시간으로 야간 인계 대기가 전체 지연에 큰 영향을 줌.
- 자동 분류 성공률은 평균 86.3%이나 결제 취소 68.1%, 계정 잠금 64.7%, 배송 주소 변경 69.4%로 세 유형이 특히 낮음.
- 세 유형은 전체 접수의 약 31%이지만 재분류 작업의 62%를 차지하여 우선 개선 대상으로 선정함.
- 현행 야간 업무는 오후 6시 이후 접수된 문의를 공용 큐에 모은 뒤 다음 날 오전에 전량 재분류하고 있어 담당자 2명이 매일 평균 1시간 20분을 사용함.

## 2. 주요 논의

### 2.1 결제 취소와 배송 주소 변경

- 현재 키워드만으로 분류하여 배송 전 주문 취소와 배송 후 환불, 출고 전 주소 변경과 출고 후 배송사 안내가 같은 큐에 섞이는 문제가 있음.
- 두 유형 모두 주문 상태를 함께 확인해야 분류 정확도를 높일 수 있음.
- 주문 API에서는 필요한 상태를 제공할 수 있으나 분류 서비스에는 아직 전달되지 않음.
- 분류 요청에는 허용된 상태 코드만 추가하고 주문 번호, 배송지, 수취인 등 고객 식별 정보는 전달하지 않기로 함.
- 내부 상태 코드는 상담 화면에 노출하지 않고 분류 판단에만 사용함.
- 운영 반영은 보안 승인과 통합 테스트를 모두 통과한 뒤 진행하며, 그 전에는 마스킹된 테스트 데이터로만 검증함.

### 2.2 계정 잠금

- “로그인이 안 된다”는 표현만으로 계정 잠금과 비밀번호 재설정 문의를 구분하기 어려움.
- 인증 전 단계에서 계정 상태를 조회하는 방식은 권한 범위가 커져 이번 개선에서 제외함.
- “여러 번 틀렸다”, “잠겼다”, “오류 횟수” 등 문장 표현을 규칙에 반영하고 확신도 임계값을 0.75로 설정함.
- 0.75 미만 건은 계정 잠금 전문 큐로 강제하지 않고 로그인 일반 큐로 전달함.
- 지난달 표본에서는 잠금 문의 412건 중 61건이 일반 큐에 남지만 오분류는 96건에서 24건으로 줄어드는 것으로 확인함.
- 임계값, 실험 표본, 판단 근거를 규칙 변경 기록에 함께 남기기로 함.

### 2.3 야간 자동 이동

- 최근 3개월 연속 자동 분류 성공률이 95% 이상인 유형만 야간 공용 큐에서 유형별 큐로 자동 이동함.
- 자동 이동 로그에는 분류 결과, 확신도, 적용 규칙 버전, 이동 전후 큐를 기록함.
- 상담사가 분류를 수정할 때 `분류 오류`, `고객 추가 정보`, `운영 예외` 중 하나를 선택하게 하고 기타 의견은 선택 입력으로 둠.
- 자유 입력란에는 개인정보를 작성하지 않도록 경고 문구를 표시함.
- 자동 이동 후 상담이 시작되기 전까지 운영 리더가 이전 큐로 복원할 수 있도록 함.
- 복원 버튼은 기존 운영 리더 역할에만 노출하고 복원 실행자, 시각, 사유를 감사 로그에 남김.

### 2.4 성과 측정 및 검증

- 핵심 지표는 `분류 처리 시간`, `최초 응답 시간`, `재분류율` 세 가지로 정함.
- 분류 처리 시간은 문의 접수부터 담당자 열람까지로 정의하고, 절대 시간과 근무시간 기준을 모두 산출함.
- 개인정보 노출과 권한 오류는 안전 지표로 별도 관리하며 허용 기준은 0건임.
- 규칙별 확신도 분포와 사용자 만족도는 참고 지표로 사용하되 시범 성공 여부의 단독 판단 기준으로 사용하지 않음.
- 비교 기준 기간은 5월 마지막 2주로 정함.
- 시범은 2주간 운영하고 첫 이틀은 안정화 기간으로 핵심 지표 비교에서 제외함.
- 테스트 표본은 전체 500건을 목표로 하고 유형별 최소 30건, 야간 문의 최소 100건을 포함함.
- 기존 상위 10개 정상 유형의 회귀 테스트와 복원 권한, 개인정보 안내 문구도 함께 확인함.

## 3. 의사결정

1. 결제 취소와 배송 주소 변경은 주문 상태 코드를 분류 입력에 추가함.
2. 주문 관련 개인정보는 전달하지 않고 허용된 상태 코드만 사용함.
3. 계정 잠금은 문장 규칙과 확신도 0.75를 적용하며 기준 미만은 로그인 일반 큐로 보냄.
4. 야간 자동 이동은 최근 3개월 연속 성공률 95% 이상인 유형으로 제한함.
5. 분류 수정 사유, 운영 리더 복원 기능, 규칙 버전 기반 감사 로그를 추가함.
6. 보안 승인, 통합 테스트 통과, 교육 완료, 교육 후 최소 2일 경과의 네 조건을 모두 충족한 다음 영업일에 시범을 시작함.
7. 시범 시작일은 준비 조건이 충족된 뒤 확정하며 현재 임의 날짜를 지정하지 않음.
8. 개인정보 노출 또는 권한 오류가 한 건이라도 발생하면 시범을 즉시 중단함.
9. 재분류율이 기준 기간보다 5%p 이상 악화되는 일반 오류는 운영팀장 판단으로 중단함.
10. 중단 후 재개는 원인 조치 완료 뒤 운영팀장과 보안 담당자가 함께 승인함.

## 5. 운영 및 중단 절차

- 시범 첫 3일은 매일 오전 10시에 15분 점검하고 이후에는 일일 지표를 공유함.
- 자동 이동 오류는 발견 즉시 운영 메신저의 시범 전용 말머리로 공유함.
- 장애 발생 시 기능 플래그로 자동 이동만 중단하고 야간 큐는 기존 수동 인계 방식으로 복귀함.
- 중단 시각, 실행자, 사유를 감사 로그에 남기며 원인 조치와 공동 승인 전에는 재개하지 않음.
- 교육 자료와 테스트에는 실제 고객 화면이나 원본 고객 데이터를 사용하지 않음.

## 6. 확인 필요

- 감사 로그 보관 기간: 기존 처리 로그와 동일한 90일을 제안했으나 보안팀 확인 전에는 미확정임.
- 실제 시범 시작일: 보안 승인, 통합 테스트, 교육 완료, 교육 후 최소 2일 경과 여부에 따라 확정함.
- 주문 상태 API 연동 일정: API 담당자와 2026-06-04 오전 협의 후 확정함.

## 7. 회의록 작성 기준

- 확정된 결정과 미확정 항목을 분리해 기록함.
- 수치와 임계값은 결정 근거를 이해하는 데 필요한 경우에만 남김.
- 동일한 설명의 반복, 인사말, 교육 간식 논의 등 업무 결정과 무관한 대화는 제외함.
- 발언 순서를 그대로 옮기지 않고 안건별로 통합하여 작성함.
