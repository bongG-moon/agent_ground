내가 쓰던 회의록의 방식은 남기고
현재 회의의 사실만 사용합니다

과거 녹취 TXT와 실제 Word/TXT 회의록의 대응 관계에서 사용자의 선택·생략·구성·문장 스타일을 추출하고, 현재 녹취와 추가 지시를 바탕으로 같은 스타일의 회의록을 작성·검토합니다.

Flow JSON 열기사용 안내연결 구조
1~10쌍과거 녹취·회의록 예시
1개현재 녹취 TXT
3회분석·작성·최종 검토
필수최종 사람 검토
과거 회의의 내용은 새 회의록으로 복사하지 않습니다.과거 자료에서는 선택·생략 기준, 제목과 섹션 순서, 문장 종결, 결정사항과 담당자 표현처럼 작성 방식만 추출합니다. 실제 사실은 현재 녹취에서만 가져옵니다.

Three input groups

파일을 세 묶음으로 나누어 넣습니다

과거 녹취와 과거 회의록은 같은 순서로 올려야 1번끼리, 2번끼리 정확히 비교할 수 있습니다.

01

과거 녹취 TXT

회의에서 실제로 어떤 말이 나왔는지 보여주는 원본입니다. 1~10개를 회의 순서대로 업로드합니다.

02

실제 작성 회의록

사용자가 과거 녹취에서 무엇을 골라 어떤 형식으로 썼는지 보여줍니다. TXT·DOCX를 지원하며 DRM 문서는 승인된 해제 API 설정을 사용합니다.

03

현재 녹취 TXT

이번에 작성할 회의의 유일한 사실 근거입니다. 파일은 정확히 한 개만 넣습니다.

Instruction priority

추가 지시는 학습된 스타일보다 우선합니다

1. 현재 녹취 사실

현재 녹취에 없는 결정, 수치, 담당자, 일정을 새로 만들지 않습니다.

2. 사용자 추가 지시

“일정과 담당자 위주”, “잡담과 기술 상세 제외”처럼 이번 회의에만 적용할 포함·제외 기준을 입력합니다.

3. 학습된 작성 스타일

과거 예시에서 추출한 구성, 압축 정도, 문장 표현과 액션아이템 형식을 적용합니다.

Pipeline

스타일 분석과 사실 작성을 분리합니다

01파일 텍스트 추출
02예시 순서 1:1 결합
03작성 스타일 분석
04현재 회의록 초안
05사실·지시·스타일 검토
06최종 회의록 출력

Ready-to-run sample

실제 장문 샘플 두 쌍으로 확인하세요

각 과거 녹취는 220개 발언이며, 대응 회의록은 Builder에 바로 넣을 수 있는 Word 파일과 내용 확인용 TXT를 함께 제공합니다. 같은 번호의 두 형식을 동시에 넣지 말고 하나만 선택합니다.

과거 예시 1·2

  • 과거 녹취 01 · 220개 발언 + Word 회의록 01 · TXT 확인본
  • 과거 녹취 02 · 220개 발언 + Word 회의록 02 · TXT 확인본

1번끼리, 2번끼리 업로드 순서로 1:1 비교하며 과거 예시는 최대 10쌍까지 추가할 수 있습니다.

현재 작성 요청

  • 현재 녹취 TXT · 220개 발언
  • 추가 지시 예시
  • 기대 결과와 확인표

현재 녹취는 한 번에 정확히 한 파일만 처리합니다.

DRM 문서 텍스트 추출

일반 문서는 로컬에서 읽고 보호 문서는 승인된 DRM text API로 평문을 추출합니다. EWS JPG/JPEG/PNG는 연결된 Vision 모델로 해석하며 미지원 형식은 안내 결과로 반환합니다.

입력
문서 파일 · EWS 파일 항목 · JPG·PNG 이미지 해석 모델 · 외 11개
출력
추출된 문서 텍스트 (Message) · 처리된 파일 (Data)
