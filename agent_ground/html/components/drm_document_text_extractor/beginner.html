이메일 안에 묶지 않고
DRM 문서 처리를 따로 재사용합니다

일반 문서는 로컬에서 읽고, 보호 문서는 승인된 DRM text API에서 평문 텍스트를 받아 요약·검색 단계로 넘깁니다.

Component 상세 보기전체 초보자 문서기술 사용 가이드
정확한 범위복호화된 원본 PDF·PPT·Excel을 배포하는 기능이 아닙니다. 승인된 경로에서 평문 텍스트 또는 임시 TXT를 만들어 다음 Component가 읽도록 하는 기능입니다.

Two inputs

직접 업로드와 이메일 첨부를 모두 처리합니다

직접 파일 업로드

document_files에 문서를 넣고 extracted_text Message를 Chat Output·요약 모델에 연결합니다.

EWS 이메일 첨부

file_record에 첨부 Data를 넣고 processed_file을 Read File에 연결합니다.

Processing modes

세 가지 처리 모드

모드처리사용 상황
자동(로컬 우선)일반 문서는 로컬, 실패 파일만 DRM API일반·보호 문서가 섞인 경우
항상 DRM API지원 문서를 승인 API로 전달보호 여부를 확실히 판별하기 어려운 경우
DRM 미사용네트워크 호출 없이 로컬 추출만 사용샘플·비보호·오프라인 테스트

Execution path

문서가 텍스트가 되는 순서

01파일 입력
02확장자·크기 검사
03로컬 추출 시도
04필요 시 DRM API
05평문 결과
06요약·검색 연결

Security check

처음 등록한 뒤 확인할 것

  • 승인된 사내 DRM endpoint만 사용합니다.
  • 토큰과 사번은 Secret 입력에 넣고 JSON에 저장하지 않습니다.
  • 운영 환경은 HTTPS와 TLS 인증서 검증을 유지합니다.
  • 평문 작업 파일의 저장 위치와 삭제 정책을 확인합니다.
  • 오류·상태·로그에 토큰, 사번과 문서 본문이 남지 않습니다.
  • 실제 사내 DRM API 확인 전까지 user_testing을 유지합니다.
